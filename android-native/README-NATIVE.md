# Нативный Android-клиент Tege

Здесь находится отдельное нативное приложение на **Kotlin + Jetpack Compose**. Оно не заменяет веб-клиент в корне репозитория и не использует Capacitor.

## Структура

- `app/src/main/java/org/tege/messenger/MainActivity.kt` — точка входа и навигация.
- `ui/screens/` — экраны авторизации, списка чатов, диалога, каналов, профиля и настроек.
- `viewmodel/TegeViewModel.kt` — состояние интерфейса и действия пользователя.
- `model/Models.kt` и `data/SampleData.kt` — модели и демонстрационные данные.
- `service/` — вспомогательные сервисы приложения.

## Сборка APK через GitHub Actions

Workflow **Build Native Android APK (Kotlin + Compose)** собирает именно этот нативный проект:

1. Откройте вкладку **Actions** в GitHub.
2. Выберите **Build Native Android APK (Kotlin + Compose)**.
3. Нажмите **Run workflow** (или откройте результат запуска после push/PR с изменениями в `android-native/`).
4. Скачайте артефакт **Tege-Native-Debug-APK** — в нём будет `app-debug.apk`.

Workflow использует JDK 17, Android SDK 34 и Gradle 8.2.1. Gradle Wrapper пока не добавлен, поэтому CI запускает установленный Gradle напрямую.

## Локальная сборка

Нужны JDK 17, Android SDK с платформой 34 и Gradle 8.2.1. Из корня репозитория выполните:

```bash
cd android-native
gradle --no-daemon assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Реализованные локальные возможности

- Поиск по названиям чатов, именам пользователей, превью и текстам сообщений из локальной истории.
- Закрепление чатов с сортировкой закреплённых выше остальных.
- Ответ на сообщение с цитатой, локальные реакции и закрепление отдельных сообщений.
- Редактирование имени, username, телефона и описания профиля.
- Переключение светлой/тёмной темы через настройки.
- Запись голосового сообщения через микрофон с запросом разрешения Android и локальное воспроизведение записи.

## Ограничения и серверная интеграция

- **Backend и синхронизация ещё не подключены.** В репозитории не обнаружен согласованный API-контракт/URL сервера для авторизации, чатов и сообщений. Выдумывать endpoint или показывать локальные изменения как синхронизированные было бы небезопасно. Для настоящей синхронизации нужен действующий backend, API-контракт, серверная авторизация и обработка конфликтов/ошибок сети.
- Чаты, ответы, реакции, закрепления и профиль изменяются в памяти текущего процесса и не синхронизируются между устройствами. Записанные аудиофайлы лежат в cache приложения и не загружаются на сервер; очистка cache может удалить их.
- Вход и аккаунты остаются демонстрационными; визуальная галочка не является серверной верификацией.
- Workflow проверяет компиляцию и сборку debug APK, но не заменяет ручное тестирование на устройстве.
- Веб/PWA и Capacitor APK собираются отдельными workflow и остаются независимыми от этого нативного клиента.


## Дополнительные возможности Android-клиента

- **Управление уведомлениями по чату:** меню диалога переключает локальный статус «отключить/включить уведомления». Это состояние интерфейса; системные push-уведомления и серверная доставка не подключены.
- **Закрепление чата:** закрепить или открепить диалог можно из меню самого диалога; закреплённые чаты сортируются выше в списке.
- **Автоматическая отметка прочитанным:** при открытии диалога локальный счётчик непрочитанных сбрасывается.
- Поиск, ответы, реакции, опросы, голосовые сообщения и видеозаметки остаются частью нативного интерфейса. Голосовые файлы и состояние приложения не синхронизируются между устройствами без backend.
